# ADR-0005: Evaluation protocol: fixed splits, leakage test, scoreboard

- Status: accepted
- Date: 2026-09-22

## Context and problem statement

Claims (field F1, trust guarantee, attack success 0, fraud recall) are only credible if splits are
fixed before training, never leak, and results are regenerated by a command rather than typed in.

## Considered options

1. **sha256-keyed `evals/splits.json` + leakage test + generated scoreboard.**
2. Random splits at run time with a seed: fragile across dataset re-downloads and re-renders.
3. Per-dataset official splits only: no cal split, no cross-set overlap check.

## Decision outcome

Option 1.

- `evals/splits.json` maps split name → sorted list of document sha256: `train`, `cal`, `test`
  for the UAE factory and FATURA; `docile_train`, `docile_val`; `extractbench_short`;
  `attack_suite`; `reality` (optional, local only). Official splits are respected where they
  exist (DocILE val is eval only, ExtractBench is eval only).
- Near-duplicate guard: factory documents sharing a template seed and ERP record stay in one
  split (split by group, then list members by sha256).
- `tests/test_no_leakage.py` fails on any sha256 overlap between train, cal, test and every
  external eval set, and on any training manifest in `ml/` that references a non-train sha256.
- Only `apx/trust` reads `cal`; only `evals/` reads `test` and external sets.
- `make eval` writes `reports/scoreboard.md` and JSON next to it, and updates the README block
  between `<!-- SCOREBOARD:START -->` and `<!-- SCOREBOARD:END -->`. Each row records dataset,
  split hash, model revisions (from `infra/models.lock.json` and MLflow), date and command.
  Estimates are never written to the scoreboard.

## Consequences

- Good: reproducible, auditable, cheap to check in CI (splits file is small; data is not).
- Bad: regenerating the factory changes sha256s, so splits must be regenerated and re-committed
  together with an ADR note when that happens.

## Proof (gate)

- `tests/test_no_leakage.py` in CI (`not gpu`), plus a negative test that injects an overlap
  and expects failure.
- `make eval-quick` produces a scoreboard with every target row present (value or "not run").
- A release audit re-runs `make eval` from a fresh clone and diffs the scoreboard.

## Amendment: declaring the split value is not reading it

The database schema records which split a corrected label belongs to (`apx/db/enums.py`,
`LabelSplit.CAL = "cal"`), which the "only `apx/trust` references cal" grep flagged. The guard
now exempts exactly that one declaration line and nothing else in the file, and in exchange also
flags any `*Split.CAL` enum-member use outside `apx/trust`. Net effect: the gate is stricter than
before (enum-based selection of cal rows was previously invisible to it), and the only mention
allowed outside `apx/trust` is the schema stating the value exists. Proof:
`tests/test_no_leakage.py::test_enum_member_use_is_flagged_and_only_the_exact_declaration_is_exempt`.
